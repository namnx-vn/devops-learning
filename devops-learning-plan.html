Cách rút ngắn: nếu vượt tiêu chí thực hành của một buổi và giải thích được, dùng thời gian đó cho phần yếu hoặc dự phòng. Không bỏ Linux/AWS chỉ vì đã làm FE lâu năm. Nếu chưa đạt checkpoint sau buổi bù, giãn lịch trước khi học tiếp phần phụ thuộc.

Chuẩn bị theo tuần: tuần 1 dùng Git, Node và Linux VM; tuần 2 thêm Docker/Compose; tuần 3 tài khoản AWS lab và CLI; tuần 4 Terraform/Jenkins; tuần 5 kind hoặc Minikube và kubectl. Kiểm tra tài nguyên máy theo tài liệu công cụ; tắt lab không dùng để tránh tranh CPU/RAM.

Một app, hai môi trường học rõ ràng

Chọn một SPA cá nhân bằng stack quen thuộc, có /dashboard và một tương tác kiểm thử được; thêm Node API tối giản cho lab container. Dùng fixture JSON cho bản cloud để tập trung vào phát hành frontend, không phát triển backend/DB mới.

Capstone chính · frontend trên AWS

Browser → CloudFront HTTPS → S3 private qua OAC. Terraform tạo hạ tầng; Jenkins test/build, lưu artifact, publish và rollback. Bản cloud chỉ dùng SPA + dữ liệu fixture cùng origin. Static hosting không chạy Node SSR.

Lab bổ trợ · Docker và Kubernetes local

Cùng SPA phục vụ qua Nginx → Node API. Tuần 2 chạy Compose; tuần 5 chuyển cùng image sang cluster local để học Service, probes và debug. API local không được khai báo thành endpoint của bản cloud.

Git → Jenkins agent → test → build → release artifact + checksum → S3 → CloudFront → browser smoke → giữ bản tốt hoặc rollback

Môi trường CI: Jenkins controller local; agent build có Node và agent deploy có AWS CLI chạy bằng user tách biệt trên host lab; chỉ bind Jenkins vào môi trường local tin cậy. Dùng SCM polling hoặc chạy build thủ công, không cần mở webhook Internet. Chỉ deploy từ branch tin cậy; quyền deploy không cấp cho bước test hoặc PR lạ. Lab dùng AWS IAM Identity Center/SSO profile trên agent tin cậy, đăng nhập trước khi chạy và làm mới khi hết hạn; nếu dùng STS session, cấp đủ access key, secret key và session token ngắn hạn chỉ trong bước deploy. Không dùng access key dài hạn để thay thế bước thiết lập này. Quyền deploy giới hạn bucket/distribution lab; agent test không được truy cập profile deploy.

Chiến lược release: asset có tên hash, giữ các asset của release còn hỗ trợ; publish HTML/config sau asset và kiểm tra metadata cache. Lưu toàn bộ artifact và config công khai theo phiên bản. Rollback phục hồi đúng artifact/config, xử lý cache rồi chạy browser smoke; không rebuild một commit cũ để giả làm artifact cũ. Lab serialize release; không cam kết cập nhật nguyên tử nhiều object hay đồng thời trên mọi browser.

Tiêu chí kết thúc: Terraform dựng lại hosting; S3 không public; HTTPS/route sâu/asset đúng; test fail chặn publish; release tốt truy vết được; bản lỗi được phát hiện và rollback; alert có ALARM/OK; sửa được ba lỗi Kubernetes; README/runbook đủ để dựng lại và dọn tài nguyên.

Để sau: EKS, multi-cloud, HA database, quản trị Jenkins/cluster, tự viết Helm chart, Ansible, SonarQube chuyên sâu và distributed tracing. Nếu công việc dùng SSR, dùng buổi mở rộng để thiết kế deploy Node/container cùng đội Platform sau khi hoàn thành các checkpoint chính.

Tuần 1 · Hiệu chỉnh nền tảng & chẩn đoán hệ thống

Tận dụng kinh nghiệm phát triển web; kiểm tra phần Linux và vận hành bằng thao tác.

15h + 3h bù
Buổi 013hĐánh giá đầu vào & chọn app90 phút: đọc Jenkinsfile, chỉ ra agent/artifact/credential và điểm chặn release; giải thích DNS → TLS → HTTP. 90 phút: tạo repo lab từ SPA cá nhân có sẵn, kiểm tra build/test và chuẩn bị Linux VM.
Buổi 023hLinux cho ứng dụng webUser, quyền file, process, port, systemd và journal. Chạy Node API tối giản có /healthz, /version và lỗi bật/tắt được trong lab; không cần database.
Buổi 033hNetworking để debugIP, subnet, route, DNS, TCP, TLS; dùng ip, ss, dig, curl. Phân biệt timeout, connection refused, lỗi TLS và HTTP 5xx.
Buổi 043hNginx, reverse proxy & browserServe SPA, proxy /api tới Node; phân biệt URL browser dùng với địa chỉ nội bộ server. Ôn CORS, cookie Secure/SameSite và forwarded headers trong luồng request.
Buổi 053hBash & checkpointViết script smoke test kiểm tra HTTP status và version, timeout, exit code; ôn quoting và pipeline lỗi. Tra tài liệu được, tự giải thích từng bước.

Checkpoint: Tự khoanh vùng 3 lỗi DNS/port/process bằng bằng chứng; chưa đạt thì dùng buổi bù trước Docker.

Buổi bù tuần 1 · 3h dự phòng: sửa phần chưa đạt, hoàn thiện setup hoặc dựng lại không theo tutorial. Ngày 7 nghỉ.

Đối chiếu workbook: Linux Lab 1–3: chọn phần quyền, service, network và script; bỏ các bài thuật toán Bash không phục vụ mục tiêu.
Đọc chọn lọc: Linux Day 1 — quản lý hệ thống & networking · Linux Day 2 — Bash scripting · Git — chỉ ôn phần chưa chắc · Jenkins — credentials, pipeline, agent

Tuần 2 · Docker & cách đóng gói frontend

Cùng SPA và API từ tuần 1; hiểu cấu hình, cache và artifact trước khi đưa lên cloud.

15h + 3h bù
Buổi 063hImage có thể dựng lạiDockerfile multi-stage, lockfile, build context, .dockerignore, base image có phiên bản; build stage và runtime stage.
Buổi 073hCấu hình & secretsPhân biệt biến được nhúng khi build với cấu hình runtime công khai. Dùng runtime-config.json cho giá trị công khai để có thể promote cùng artifact; secret chỉ ở server/CI.
Buổi 083hCompose & đường đi requestCompose chạy Nginx/SPA và Node API; service DNS, port publish, health check, log và SIGTERM. Browser gọi /api qua Nginx, không gọi hostname api trong mạng Docker.
Buổi 093hCache & release frontendHTML/config có chính sách kiểm tra lại; asset có tên hash và cache dài. Tách cache browser, proxy/CDN và service worker; capstone chưa bật service worker.

Tuần 3 · AWS phù hợp với frontend

Capstone cloud là SPA trên S3 private + CloudFront HTTPS. API vẫn là lab local; bản cloud dùng fixture JSON cùng origin.

15h + 3h bù
Buổi 113hIAM, chi phí & mô hình cloudTạo môi trường học riêng; MFA, danh tính không phải root, credentials tạm thời và least privilege. Đặt budget trước khi tạo tài nguyên; đọc shared responsibility.
Buổi 123hS3 private & artifactConsole/CLI: bucket private, Block Public Access, object metadata và policy. Dùng bucket lab riêng; học khái niệm versioning và retention.
Buổi 133hCloudFront & HTTPSDùng S3 REST origin + Origin Access Control (OAC), giới hạn bucket policy theo distribution; đặt default root object là index.html. Dùng hostname HTTPS mặc định; domain riêng/ACM là bài mở rộng.
Buổi 143hSPA routing & cache CDNRewrite các route ứng dụng đã biết về /index.html bằng CloudFront Function; không rewrite /assets hoặc file thiếu. HTML/config dùng cache policy có minimum TTL 0; assets hash dùng cache dài.
Buổi 153hAWS checkpoint & quyết định kiến trúcSo sánh static hosting với Node SSR/container; đọc VPC, Security Group, EC2, ALB ở mức kiến trúc. Thử release v2 và restore HTML/config v1, giữ asset hash cũ.

Checkpoint: HTTPS chạy được, bucket không public, route sâu và missing asset đúng, giải thích được giới hạn của static hosting.

Buổi bù tuần 3 · 3h dự phòng: sửa phần chưa đạt, hoàn thiện setup hoặc dựng lại không theo tutorial. Ngày 7 nghỉ.

Đối chiếu workbook: AWS IAM Lab 1: làm danh tính/quyền, hoãn phần Terraform EC2. AWS Lab 3: bản điều chỉnh dùng S3 private + CloudFront; không làm public website endpoint. Lab VPC/NAT/ASG không bắt buộc tạo.
Đọc chọn lọc: AWS IAM — file riêng · AWS S3 — file Module 6 (nội dung ghi Module 4) · AWS Module 3 — Networking · AWS Module 2 — Computing · AWS Module 7 — Route 53 · AWS IAM — MFA, credentials tạm thời và least privilege · AWS Budgets — cảnh báo và độ trễ · CloudFront — S3 private origin và OAC · AWS sample — URL rewrite; cần điều chỉnh cho route SPA về /index.html · CloudFront — version hóa tên file và cập nhật nội dung

Tuần 4 · Terraform & làm chủ quy trình release

Tái tạo hạ tầng đã hiểu, rồi nối Jenkins. Tập trung review và độ tin cậy thay vì học lại khái niệm stage.

15h + 3h bù
Buổi 163hTerraform căn bảnProvider, resource, variable, output, plan/apply/destroy và state. Tạo một bucket sandbox mới bằng code; dùng credentials ngoài .tf; chốt phiên bản và commit lockfile.
Buổi 173hCodify static hostingMở rộng stack sandbox: CloudFront, OAC, bucket policy, cache behavior và route rewrite đã học. Terraform quản lý hạ tầng; release script quản lý nội dung SPA.
Buổi 183hDrift, state & quyền deployGây drift một tag rồi phát hiện bằng plan. Bảo vệ state local trong lab một người; đọc remote state/locking trước khi áp dụng nhóm. Tách quyền provision với quyền upload/invalidate của pipeline.
Buổi 193hJenkins: kiểm tra → build → lưu releaseDùng controller lab local, agent build/deploy tách user theo kiến trúc đã chọn, hoặc Jenkins sandbox đã được phép dùng; SCM polling cho local. Kiểm tra lại artifact, credential scope, timeout và lưu dist theo commit/checksum.
Buổi 203hJenkins: publish, smoke test, rollbackAgent dùng AWS CLI và credentials tạm thời có quyền giới hạn; có bước làm mới khi hết hạn. Serialize deployment; upload assets trước, config/HTML sau, invalidate cần thiết và chờ hoàn tất.

Checkpoint: Terraform dựng được hosting; pipeline chặn test fail, lưu đúng artifact, deploy và rollback bằng phiên bản đã lưu.

Buổi bù tuần 4 · 3h dự phòng: sửa phần chưa đạt, hoàn thiện setup hoặc dựng lại không theo tutorial. Ngày 7 nghỉ.

Đối chiếu workbook: Linux Lab 5 chỉ để tham khảo cú pháp Terraform local. Không ép làm AWS Lab 1–2 theo template EC2/VPC; thay bằng S3/CloudFront sát mục tiêu. CI/CD Lab: chọn Git + Jenkins + Terraform + AWS, bỏ phần DB/Ansible bắt buộc.
Đọc chọn lọc: Linux Day 4 — Terraform · Jenkins — credentials, pipeline, agent · Terraform — S3 backend, bảo vệ state và locking · Jenkins — giới hạn credentials với pipeline không tin cậy · Jenkins — lưu pipeline trong Jenkinsfile

Tuần 5 · Kubernetes để phối hợp và xử lý sự cố

Lab local với kind hoặc Minikube; cùng image từ tuần 2. Đọc cấu hình và vận hành workload ở mức ứng dụng.

15h + 3h bù
Buổi 213hDeployment & ServiceCài cluster local; học Pod, Deployment, Service, namespace, YAML và kubectl. Load image local theo hướng dẫn của công cụ; FE proxy API qua Service.
Buổi 223hConfig, probes & resourcesConfigMap, Secret khái niệm, requests/limits, startup/readiness/liveness. Không coi Secret là mã hóa mặc định; cấu hình công khai của SPA vẫn tải qua runtime-config.
Buổi 233hDebug có hệ thốngDùng logs, describe, events và endpoints để phân biệt image lỗi, crash, selector/port sai. Chỉ gây lỗi trong namespace lab.
Buổi 243hRollout & rollbackUpdate image theo version, theo dõi rollout status; triển khai bản readiness lỗi rồi phục hồi bản tốt. Phân biệt rollback image với thay đổi ConfigMap ngoài Deployment revision.
Buổi 253hHandoff với đội PlatformĐọc values của một Helm chart mẫu, Ingress/TLS khái niệm; thống nhất health endpoint, resource budget, config, secret owner và deploy permissions.

Checkpoint: Tự đọc manifest, tìm đúng log, sửa ba lỗi và rollback; quản trị cluster, EKS và Helm chart tự viết là phần mở rộng.

Đọc chọn lọc: Kubernetes Session 7 — bắt đầu; học tiếp Session 8–10 cùng thư mục · Helm — đọc chart và values · Kubernetes — startup, readiness và liveness · kind — quick start và load image local

Tuần 6 · Độ tin cậy, vận hành & chuẩn hóa cho team
